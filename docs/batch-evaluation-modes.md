# 批量对话评测模式

入口：管理端「批量对话测试」，接口 `POST /api/evaluations`。上传 JSON/CSV 或手工编辑题目后，任务在后台执行，JSON/CSV 下载包含批次、轮次、问题、完整回复和任务选项。

## 题目来源与标签

页面「载入示例」提供代码内的 3 道演示题，不是外部标准评测数据。真实题目由管理员导入。`test` 与 `validation` 仅用于分类，执行方式相同，不会训练模型、自动拆分数据或自动计算正确率。「成功」表示执行完成，不代表答案正确。最多 500 题，每批最多 100 轮。

## 任务选项

| 字段 | 默认 | 行为 |
| --- | --- | --- |
| `concurrency` | `1` | 1–8 个独立批次并发，同批追问始终按轮次串行。并发提高吞吐，不降低总 token 用量。 |
| `strictMode` | `false` | 只输出校园导览相关的中性文字；停用卡片、彩蛋、技能资料与外部工具，保留知识检索。 |
| `knowledgeScope` | `mounted` | `mounted` 使用已挂载知识库；`v2-only` 仅查询校园事务 2.0 的 SQLite 与 Markdown 两库。 |
| `bypassCache` | `true` | 默认实时生成。关闭后可复用相同权限及模式的服务器缓存。 |
| `outputPreference` | `adaptive` | 普通任务选择新式排版、固定卡片或文字为主；严格模式强制纯文字。 |

示例请求（模型及智能体 ID 按部署实际配置）：

```json
{
  "title": "校园多轮测试",
  "format": "json",
  "data": "{\"batches\":[{\"id\":\"通勤\",\"questions\":[\"良乡校区附近的地铁站是哪个？\",\"怎么去？\"]}]}",
  "concurrency": 2,
  "strictMode": true,
  "knowledgeScope": "v2-only",
  "bypassCache": true
}
```

## 严格模式

生成正文与推理不会直接流出。完整回答先转换为纯文字，再通过一次不带工具的独立语义审核，核对校园导览相关性、中性表达、敏感内容和证据支持。审核不通过、结果不完整或审核服务异常时，保存中性回退提示；原始推理、未通过的正文及工具上下文不保存为可见聊天内容。

审核调用的 token 纳入原消息及正常额度，并在运行指标 `strictReview` 中保留审核状态；任务耗时包含审核。命中已审核缓存时不重复调用。语义审核仍可能误判，正式评测需要人工核对，不能将此机制描述为对任意输入的绝对保证。严格模式不对未审核的来源摘要生成卡片或导出正文摘要。

## 仅 2.0 两库

两库须已导入、未移除，并在执行账号的授权范围内；需要校园知识读取权限。任务使用独立索引，目录、初始检索及后续查询工具均受同一范围约束。该模式允许管理员评测已导入但全站关闭的两库，不改变线上学生会话的挂载配置。外挂固定回答、关键词彩蛋、其他技能资料和外网工具不加入本任务。两库包含赛事模拟记录，不代表实时校方业务数据。

## 顺序、取消与导出

不同批次使用独立会话；前一轮失败只跳过本批后续追问，其他批次继续。停止任务中断在途生成并阻止下一题；已完成结果仍可下载。任务重启后明确标记中断，不自动重新调用模型。结果始终按原始题目顺序导出，JSON 的 `task.options` 和 CSV 的 `options` 保留并发、严格模式和知识库范围。

本地回归：`verify-evaluation-policy.ts`、`verify-evaluation-platform.ts`、`verify-agent-runtime.ts`、`verify-evaluation-ui.mjs`。集成测试仅允许本地 PostgreSQL，使用模拟模型；不会调用真实付费接口。
