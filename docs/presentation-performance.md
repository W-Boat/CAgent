# 新式排版与加载性能

完整卡片在后续文字追加时复用解析结果及组件数据，不再每次重新归一化和校验。缓存属于当前挂载的回答，最多保存 24 个完整块、约 256K 字符；不会成为跨用户的全局回答缓存。来源授权发生变化时重新校验；手动重渲会重新创建解析器。

未完成的 JSON 保持占位，不提前开放交互；完整卡片通过原有校验后显示。终态与流式阶段使用同一份卡片数据，避免因结束生成而重新挂载。历史围栏、异常结构及纯文字回退继续沿用统一格式器。

管理端、学生端和体验页在异步组件尚未加载时即显示轻量占位。准备、整理上下文、查询、生成和恢复阶段使用实际运行事件；已有正文后显示“正在补充回答”，不继续卡在准备阶段。卡片占位提示已有文字可以先阅读；较长等待提供继续等待或停止的说明。加载不使用虚构百分比，兼容夜间主题及减少动态效果偏好。

后端并行读取彼此独立的地图上下文、地图开关和关键词规则，固定回答的优先级仍按原策略处理。检索直接使用已加载索引的条数和快照元信息，避免每次查询额外扫描知识目录及执行全库计数；独立评测范围保持隔离。

回归入口：

```sh
pnpm --filter @cagent/api exec node scripts/verify-presentation-speed.mjs
pnpm --filter @cagent/api exec node scripts/verify-presentation-speed-ui.mjs
```

第一项验证连续追加时的对象复用、来源重新授权、缓存边界及旧格式兼容，并报告本地投影耗时。第二项使用模拟 API 与分段回答验证三端加载提示、卡片节点稳定性、原始 JSON 隐藏及终态清理；设置 `UI_WEB` 可选择已构建页面的访问地址。两项均不调用真实模型。

该基准只测本地排版处理；实际首字及完整回答耗时仍受模型、网络、检索内容与上下文长度影响。
