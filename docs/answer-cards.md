# 答复卡片排版

学生端、管理端聊天和 `/test` 使用同一个 `CardMessage` 渲染组件，统一卡片、Markdown、流式占位与来源去重。追问、切换智能体、技能选择、地图和互动效果仍通过组件事件处理。

按内容使用具体排版：真实主题分区 `sections`、可展开问答 `faq`、事项提示 `notice`、普通情绪关怀 `care`、地点详情 `places`，以及原有关键字段、步骤、清单、时间线与比较表。短主题宽屏并排，手机单列；长节保持通栏。没有“要点整理/信息整理”眉标和重复大标题。历史 `reading` 保留全文，以无外框阅读样式显示。正文沿用现有安全 Markdown 渲染器，不执行 HTML；实际链接点击继续进入导览统计。

地点和办事入口卡片区分线上、线下与两种方式。线上使用网页 SVG 图标与「线上办理」标识，入口为「前往线上办理」；线下使用定位 SVG 图标，窗口或一般地点分别标记「线下窗口」「线下地点」，地址放在独立信息区，资料链接为「查看窗口详情」或「查看地点详情」。图标与文字共同表达类型，配色继承统一主题，夜间模式沿用已有颜色变量。

支持可选 `items[].serviceMode=online|offline|hybrid`。历史没有该字段时，从明确位置和办理描述辨认，单有链接不推定可在线办，资料里的不支持线上办理表述优先处理；不明确的保留中性「服务信息」。纯「线上」位置不重复显示为办理地址，其他位置说明仍完整保留。已有具体链接文案保留，笼统「查看详情」随办理方式改为明确动作；链接仅允许无内嵌凭据的 HTTP(S)，站内追问事件和外链点击统计保持现有处理。

回复完成后，多个同级主题可自动分区，保留子标题与标题中的链接；普通清单、表格、长文使用原有 Markdown，不再因篇幅而套整理卡。这个过程只改变呈现方式，不增加模型调用，不补编事实，不删除日期、条件、链接或表格单元格。代码与流式正文保持原样，避免半段内容不断变换布局。

普通压力或难过时，关怀卡提供针对具体处境的陪伴和可选追问；自伤、自杀或立即危险的求助卡 `crisis` 仍优先，电话号码使用原有固定常量并忽略模型给出的号码。`options`、`steps`、`poem`、`article`、`agents`、`map`、`effect` 原有组件和事件均保留，不由分节卡替代。

后端聊天路径提供统一的简短排版规则，适用于学生、管理和体验聊天，也覆盖仍保存旧卡片提示的会话。新规则使用现有预留 token 预算，引导模型选择合适的卡片，并禁止生成 `sources` 资料来源卡、索引编号字段和重复来源列表。

真实模型偶尔将卡片 JSON 标为 `json` 而非约定的 `card`，旧解析器因而显示代码、看似卡片消失。解析器现对完整 `json` 围栏进行已知类型与必需字段校验，合法卡片进入同一组件，普通 JSON、未知类型和缺少字段的对象保持代码原样；未完成的 JSON 也不提前转换。系统提示同时明确要求使用 `card` 围栏。

兼容旧 `<card type="…">JSON</card>` 数据标签，要求标签类型与 JSON 类型一致且字段可用；代码示例里的标签不会转为卡片，不执行 HTML。模型可能完全省略卡片，因此服务在成功完成回复后，对明确的个人情绪倾诉补充短关怀入口，对现有紧急求助判定补充固定求助卡；已有相应卡片不重复添加，失败或中断不补卡，也不额外调用模型。原模型正文和实际 token 账单保持不变，补充卡片随 SSE 与历史正文保存。

实际知识库引用与参考依据仍由独立「知识库来源」区域展示。历史回复如果已有知识库来源，正文里的旧 `sources` 卡片隐藏；没有独立来源元数据的历史回复保留唯一的来源卡，以免丢失已有链接。

验证脚本 `apps/api/scripts/verify-answer-ui.mjs` 使用三端真实浏览器和隔离 SSE 响应，检查具体主题分区、普通内容无整理框、关怀/求助及七类原卡、固定热线、步骤交互、完整条件与长比较表、问答展开、来源去重、追问与链接统计、按需代码高亮、手机布局及明暗主题。测试不调用模型，临时空会话会软删除；生产验证的模拟回复和点击事件不会写入实际学生聊天或运营统计。

排版方向参考[灵光官方产品介绍](https://apps.apple.com/cn/app/%E7%81%B5%E5%85%89-%E5%85%A8%E6%A8%A1%E6%80%81ai%E5%8A%A9%E6%89%8B/id6751496092)中按内容提供可视化、可交互答案的方式；本项目使用受控 Vue 组件，不运行模型生成的页面代码。
